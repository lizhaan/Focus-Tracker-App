# Attention Tracker — математика застосунку

Цей документ — **єдине джерело правди** для всіх формул, порогів і кроків
калібрування. Код має реалізовувати саме те, що описано тут. Якщо щось
неможливо або суперечить іншому документу — пріоритет у цього файлу, а
відхилення треба явно погодити.

Загальні правила для коду:

- Усі тривалості вимірюються **в секундах за `time.monotonic()`** (мітка часу
  кадру), а не в кількості кадрів — FPS вебкамери плаває.
- Кадр для обробки **не дзеркалиться**. Дзеркальне відображення — тільки для
  показу превʼю користувачу.
- Усі геометричні обчислення з landmark-ами — **у пікселях**
  (`u = x·W, v = y·H`), бо нормалізовані `x` і `y` мають різний масштаб, коли
  `W ≠ H`.
- Усі формули реалізуються як **чисті функції** (без Qt, без глобального
  стану), щоб їх можна було покрити unit-тестами.

## 1. EAR — відкритість очей

Для кожного ока (індекси з таблиці 0.1, в пікселях):

```
EAR_eye = ( dist(P2, P6) + dist(P3, P5) ) / ( 2 · dist(P1, P4) )
```

- праве око: `P1=33, P2=160, P3=158, P4=133, P5=153, P6=144`
- ліве око: `P1=362, P2=385, P3=387, P4=263, P5=373, P6=380`

```
EAR(t) = (EAR_right + EAR_left) / 2
```

Сам по собі `EAR < поріг` ще не тригер — потрібна часова умова (розділ 4).

## 2. Поза голови: Yaw, Pitch, Roll

### 2.1 3D-модель обличчя

Модель задається **в системі координат камери OpenCV** (X — вправо в кадрі,
Y — **вниз**, Z — від камери вглиб сцени). Тоді для обличчя, повернутого
прямо в камеру, `R ≈ I`, і кути коло нуля без стрибків через ±180°.

| Точка (індекс) | (X, Y, Z), умовні мм |
|---|---|
| Кінчик носа (1) | (0, 0, 0) |
| Підборіддя (152) | (0, 63.6, 12.5) |
| Зовн. кут правого ока (33), ліва частина кадру | (−43.3, −32.7, 26.0) |
| Зовн. кут лівого ока (263), права частина кадру | (43.3, −32.7, 26.0) |
| Правий кут рота (61), ліва частина кадру | (−28.9, 28.9, 24.1) |
| Лівий кут рота (291), права частина кадру | (28.9, 28.9, 24.1) |

### 2.2 Камера (наближено)

```
camera_matrix = [ f  0  W/2 ]     f = W (ширина кадру в px)
                [ 0  f  H/2 ]     dist_coeffs = 0
                [ 0  0   1  ]
```

### 2.3 Розвʼязання

```
ok, rvec, tvec = cv2.solvePnP(object_pts, image_pts_px, camera_matrix, dist_coeffs,
                              flags=cv2.SOLVEPNP_ITERATIVE,
                              useExtrinsicGuess=<є попередній rvec/tvec>,
                              rvec=prev_rvec, tvec=prev_tvec)
R, _ = cv2.Rodrigues(rvec)

Pitch = atan2( R[2,1], R[2,2] )
Yaw   = atan2( −R[2,0], √(R[2,1]² + R[2,2]²) )
Roll  = atan2( R[1,0], R[0,0] )                (радіани → градуси)
```

Якщо `ok == False`, кадр вважається **невалідним** (розділ 4.1).
`prev_rvec/prev_tvec` скидаються, коли обличчя втрачено.

### 2.4 Робочі значення

```
ΔYaw(t)    = wrap( Yaw(t)   − yaw_baseline )
ΔPitch(t)  = wrap( Pitch(t) − pitch_baseline )
pitch_down(t) = s_pitch · ΔPitch(t)            (> 0 означає "голова нахилена вниз")
```

`yaw_baseline, pitch_baseline` — з активного профілю калібрування.
`s_pitch ∈ {+1, −1}` — знак, який визначається під час калібрування
(крок 3). Тому код не залежить від того, в який бік OpenCV рахує знак кута.
Для моделі 2.1 очікується `s_pitch = +1`.

## 3. Погляд (gaze)

### 3.1 Сирі сигнали

Для кожного ока беремо `C_L` — кут ока, що **лівіше в кадрі**, `C_R` — кут
ока, що **правіше в кадрі**, і `I` — центр райдужки (усе в пікселях):

| | `C_L` | `C_R` | `I` |
|---|---|---|---|
| праве око | 33 | 133 | 468 |
| ліве око | 362 | 263 | 473 |

```
e      = C_R − C_L
w      = ‖e‖
û      = e / w                         (одинична вісь ока)
n̂      = (−û_y, û_x)                   (перпендикуляр, напрямлений вниз у кадрі)
M      = (C_L + C_R) / 2

g_eye  = ( (I − C_L) · e ) / w²         горизонтальна позиція райдужки, ≈ 0.3…0.7
v_eye  = ( (I − M) · n̂ ) / w            вертикальне зміщення, > 0 = погляд вниз
```

```
Gaze_h(t) = (g_right + g_left) / 2
Gaze_v(t) = (v_right + v_left) / 2
```

Чому так: обидва ока рахуються в **одному напрямку кадру**, тож коли
дивишся вбік, сигнали обох очей зсуваються однаково і **підсилюють** один
одного (а не гасять, як у варіанті `D(out)/D(in)`). Проєкція на вісь ока
компенсує нахил голови (Roll). Ділення на `w` прибирає залежність від
відстані до камери.

Вертикальний сигнал через вебкамеру слабкий (повіка рухається разом з
райдужкою). Тому вертикальне відволікання в основному ловиться через
`pitch_down` і `sy`, у яких є внесок ΔPitch.

### 3.2 Заморожування під час моргання

Коли очі майже закриті, landmark-и райдужки нестабільні. Тому:

```
якщо EAR(t) < ear_freeze:   Gaze_h(t), Gaze_v(t) ← останні значення, коли EAR ≥ ear_freeze
ear_freeze = 0.7 · EAR_bottom              (EAR_bottom — з калібрування, крок 4)
```

### 3.3 Точка погляду на екрані (регресія)

Вектори ознак:

```
φx = [ Gaze_h,  ΔYaw,   Gaze_h²,  Gaze_h · ΔYaw  ]
φy = [ Gaze_v,  ΔPitch, Gaze_v²,  Gaze_v · ΔPitch ]
```

Ознаки стандартизуються параметрами, збереженими під час калібрування:

```
φ̃ = (φ − μ) / σ           (поелементно; якщо σ_k < 1e-6, то σ_k = 1)
```

Прогноз:

```
sx = cx₀ + φ̃x · cx + off_x
sy = cy₀ + φ̃y · cy + off_y
```

`cx₀, cx (4 коеф.), cy₀, cy (4 коеф.), μx, σx, μy, σy` — з калібрування
(розділ 7.4). `off_x, off_y` — поправка дрейфу з перецентрування на початку
сесії (розділ 7.6), за замовчуванням 0.
`(sx, sy)` — нормалізовані координати робочого монітора: (0,0) — верхній
лівий кут, (1,1) — нижній правий.

### 3.4 Чи погляд на екрані (гістерезис)

Застосунок працює з **одним робочим монітором** — тим, для якого
активний профіль калібрування. Погляд на будь-що поза ним (зокрема на
інший монітор, якщо він є) вважається відволіканням.

```
inside(ε)  = −ε ≤ sx ≤ 1+ε  AND  −ε ≤ sy ≤ 1+ε

якщо on_screen(t−1) == True:
    on_screen(t) = inside(ε_out)
інакше:
    on_screen(t) = inside(ε_in)

gaze_out(t) = ¬on_screen(t)
```

`ε_out = 0.05`, `ε_in = 0.02`. Гістерезис потрібен, щоб тригер не "мигав",
коли погляд точно на межі.

## 4. Сигнал відволікання `distracted(t)`

### 4.1 Валідність кадру

Кадр **невалідний**, якщо виконується хоча б одна умова:

- обличчя не знайдено;
- `solvePnP` повернув `ok=False`;
- `|ΔYaw| > 45°` або `|ΔPitch| > 40°` (голова сильно відвернута — райдужку
  вже не можна читати).

```
якщо кадр невалідний і з останнього валідного кадру минуло ≤ T_noface:
    distracted(t) = distracted(t−1)                 (короткий збій — тримаємо останнє)
якщо кадр невалідний довше T_noface:
    distracted(t) = True,  reason = FACE_ABSENT (немає обличчя) / HEAD_AWAY (кути завеликі)
    фільтри розділу 5 і стан гістерезису 3.4 скидаються
```

### 4.2 Погляд у телефон / вниз

```
eyes_low(t)  = ear_enabled AND EAR(t) < ear_threshold
head_down(t) = pitch_enabled AND pitch_down(t) > pitch_threshold

phone_eyes(t) = eyes_low(t)  безперервно протягом ≥ T_blink
phone_head(t) = head_down(t) безперервно протягом ≥ T_blink
phone_look(t) = phone_eyes(t) OR phone_head(t)
```

"Безперервно протягом ≥ T" означає: умова true на всіх кадрах з
`t_cond_start` до `t`, і `t − t_cond_start ≥ T`. `T_blink = 0.5 с` —
звичайне моргання (0.1–0.4 с) не спрацьовує.

### 4.3 Підсумок

```
distracted(t) = invalid_long(t) OR gaze_out(t) OR phone_look(t)
```

Разом з `distracted` повертається причина (`reason`) з пріоритетом:
`FACE_ABSENT / HEAD_AWAY > PHONE_HEAD > PHONE_EYES > GAZE_OUT > NONE`.
Причина пишеться в історію для аналітики.

## 5. Згладжування

Застосовується до `EAR, Yaw, Pitch, Gaze_h, Gaze_v` (до ΔYaw/ΔPitch
застосовується вже після віднімання baseline і `wrap`). Згладжування
відбувається **до** розділів 3.3–4.

```
x_med(t) = median( x(t−k+1), …, x(t) )          k = 5
x̂(t)    = α · x_med(t) + (1 − α) · x̂(t−1)      α = 0.35,  x̂(перший) = x_med(перший)
```

Медіана прибирає одиничні викиди, EMA згладжує залишковий шум.
Фільтри скидаються, коли обличчя втрачено довше `T_noface`. **У
калібруванні згладжування не застосовується** — там використовується
робастне середнє (7.1).

## 6. Машина станів фокусу

Чотири стани: `FOCUSED`, `NOT_FOCUSED`, `LOST_FOCUS`, `RECOVERING`.
Вхід — `distracted(t)` і `t` (секунди monotonic). Параметри: `n` (скільки
відволікання до втрати фокусу), `y` (скільки стабільного повернення до
відновлення), `τ` (допуск на шум).

```
старт робочої фази Pomodoro → FOCUSED

FOCUSED:
    distracted                                → NOT_FOCUSED,  t_start ← t

NOT_FOCUSED:
    (t − t_start) ≥ n і distracted            → LOST_FOCUS
    ¬distracted безперервно ≥ τ               → FOCUSED
    (коротке повернення < τ таймер n НЕ скидає)

LOST_FOCUS:
    ¬distracted                               → RECOVERING,   t_return ← t

RECOVERING:
    distracted безперервно ≥ τ                → LOST_FOCUS    (повернення зірвалось)
    (t − t_return) ≥ y                        → FOCUSED
    (одиничні кадри distracted < τ таймер y НЕ скидають)
```

Відповідність опису ідеї: етап "після повернення погляду → NOT FOCUSED,
поки не пройде y секунд" — це стан `RECOVERING`. В інтерфейсі його можна
підписати як "Повертаємось у фокус", але в коді це **окремий стан**, бо
поводиться інакше, ніж `NOT_FOCUSED`.

| Стан | Індикатор | Плашка | Pomodoro (робоча фаза) |
|---|---|---|---|
| FOCUSED | зелений | прихована | йде |
| NOT_FOCUSED | жовтий | прихована | йде |
| LOST_FOCUS | червоний | **"Фокус втрачено"** | **пауза** |
| RECOVERING | помаранчевий | "Повертаємось…" + прогрес `(t−t_return)/y` | пауза |

Значення за замовчуванням: `n = 3 с`, `y = 2 с`, `τ = 0.3 с`.

`n` і `y` користувач змінює в налаштуваннях (`n ∈ [1, 30] с`,
`y ∈ [0.5, 15] с`). Нові значення діють з наступного кадру, зокрема в
поточній сесії. Якщо зміна сталася в `NOT_FOCUSED` або `RECOVERING`,
`t_start` і `t_return` не скидаються: вже накопичений час просто
порівнюється з новим `n` або `y`.

## 7. Калібрування

Профіль калібрування привʼязаний до **(user_id, monitor_id, camera_id)**.
Калібрується **робочий монітор**, який користувач вибирає в UI. Майстер
відкривається на весь екран саме на ньому, і цілі показуються як точки на
цьому моніторі. Можна зберегти кілька профілів (наприклад, вдома й в
офісі), але в сесії завжди активний **один**.

### 7.0 Перевірка перед стартом

Обличчя видно на ≥ 90 % кадрів за 2 с. Відстань між центрами райдужок
`dist(p468, p473)` — у межах `[0.08·W, 0.30·W]` (інакше "сядьте
ближче/далі"). FPS ≥ 15.

### 7.1 Збір даних на одному кроці

- Ціль/інструкція показується `T_calib = 2.0 с`.
- Перші `T_settle = 0.6 с` **відкидаються** (очі ще переводяться на ціль).
- Протягом решти часу записуються **сирі** (незгладжені) `EAR, Yaw, Pitch,
  Gaze_h, Gaze_v` з валідних кадрів.
- Якщо валідних кадрів < 70 % — крок повторюється з підказкою (світло,
  відстань, не рухатись).
- Значення кроку — робастне середнє: відкинути точки з
  `|x − median| > 3·MAD`, потім `mean` від решти.

### Крок 1 — центр

Ціль: `(0.5, 0.5)`, голова прямо.

```
yaw_baseline   = mean(Yaw)
pitch_baseline = mean(Pitch)
EAR_center     = mean(EAR)
```

Точка додається в набір регресії: `(Gaze_h, Gaze_v, ΔYaw=0, ΔPitch=0) → (0.5, 0.5)`.

### Крок 2 — сітка (8 точок, голова нерухома)

Цілі: `(0.05,0.05) (0.5,0.05) (0.95,0.05) (0.05,0.5) (0.95,0.5)
(0.05,0.95) (0.5,0.95) (0.95,0.95)`. Користувач переводить **тільки очі**.
Для кожної точки в набір регресії йде
`(Gaze_h, Gaze_v, ΔYaw, ΔPitch) → (sx_j, sy_j)`.

### Крок 3 — повороти голови (12 точок)

Користувач повертає голову в задане положення. UI показує індикатор: крок
записується тільки тоді, коли кут у цільовому діапазоні. Погляд — на
показану ціль.

| Поза голови | Цільовий кут | Цілі погляду |
|---|---|---|
| вліво | ΔYaw ∈ [10°, 25°] за модулем | (0.05,0.5), (0.5,0.5), (0.95,0.5) |
| вправо | ΔYaw ∈ [10°, 25°] за модулем, протилежний знак | ті самі 3 |
| вгору | ΔPitch ∈ [8°, 20°] за модулем | (0.5,0.05), (0.5,0.5), (0.5,0.95) |
| вниз | ΔPitch ∈ [8°, 20°] за модулем, протилежний знак | ті самі 3 |

Ці точки вчать регресію, що поворот голови при тому самому погляді **не**
повинен зсувати `(sx, sy)`. Це і є компенсація повороту голови.

Знак нахилу:

```
s_pitch = sign( mean(ΔPitch) у позі "вниз" )
```

Якщо `|mean(ΔPitch)| < 5°` у позі "вниз" — крок повторюється.

### Крок 4 — низ екрана

Ціль: смуга внизу екрана `(0.5, 0.97)`. Дивитись природно, не моргати
навмисно.

```
EAR_bottom = mean(EAR)
PD_bottom  = mean(s_pitch · ΔPitch)
```

### Крок 5 — погляд на телефон / стіл

Інструкція: "Подивіться на телефон у руках або на стіл перед клавіатурою, як
зазвичай". Таймер звуковий/текстовий, бо користувач не дивиться на екран.

```
EAR_phone = mean(EAR)
PD_phone  = mean(s_pitch · ΔPitch)
```

### 7.2 Пороги

```
якщо EAR_bottom − EAR_phone ≥ 0.03:
    ear_enabled   = True
    ear_threshold = (EAR_bottom + EAR_phone) / 2
інакше:
    ear_enabled   = False         (EAR не розрізняє ці випадки — покладаємось на pitch і gaze)

якщо PD_phone − PD_bottom ≥ 5°:
    pitch_enabled   = True
    pitch_threshold = max( (PD_bottom + PD_phone) / 2,  PD_bottom + 4° )
інакше:
    pitch_enabled   = False       (нахил голови не розрізняє ці випадки — покладаємось на EAR і gaze)

ear_freeze      = 0.7 · EAR_bottom
```

Поріг береться **посередині** між "дивлюсь на низ екрана" і "дивлюсь у
телефон". Тому погляд на низ екрана гарантовано не спрацьовує як телефон.

Якщо користувач дивиться в телефон переважно очима, нахил голови майже не
змінюється, і будь-який фіксований запас над `PD_bottom` спрацьовував би від
звичайних змін пози (±5–10°). Тому в цьому випадку перевірка нахилу
вимикається так само, як EAR. Дуже сильний нахил голови все одно ловиться як
`HEAD_AWAY` (розділ 4.1). Якщо вимкнені обидві перевірки, телефон окремо не
визначається — лишаються `gaze_out` і `HEAD_AWAY`.

### 7.3 Набір даних регресії

1 (центр) + 8 (сітка) + 12 (повороти) = **21 точка**.

### 7.4 Навчання регресії (ridge)

Окремо для `sx` (ознаки `φx`) і `sy` (ознаки `φy`):

```
Φ  — матриця 21 × 4 ознак
μ  = mean(Φ, axis=0),  σ = std(Φ, axis=0)  (σ_k < 1e-6 → 1)
Φ̃ = (Φ − μ) / σ
c₀ = mean(s)                               (s — вектор цільових sx або sy)
c  = (Φ̃ᵀΦ̃ + λI)⁻¹ Φ̃ᵀ (s − c₀)           λ = 0.05
```

Ridge (`λ`) потрібен, бо точок мало, а ознаки корелюють. Без нього
коефіцієнти нестабільні.

### 7.5 Перевірка якості

Після навчання показуються **4 випадкові нові точки** (не з сітки).
Для кожної рахується `err = ‖(sx, sy) − ціль‖₂`.

```
calib_error = mean(err)
calib_error ≤ 0.08  → OK, профіль зберігається
0.08 < … ≤ 0.15     → зберегти з попередженням "точність знижена"
> 0.15              → запропонувати повторити калібрування
```

### 7.6 Швидке перецентрування на початку сесії

Перед кожною сесією — один крок "дивіться в центр" (2 с) на робочому
моніторі:

```
yaw_baseline, pitch_baseline ← нові середні
(sx_c, sy_c) = прогноз регресії для зібраних Gaze_h, Gaze_v при ΔYaw=ΔPitch=0
off_x = 0.5 − sx_c,   off_y = 0.5 − sy_c
якщо |off_x| > 0.15 або |off_y| > 0.15 → "Положення сильно змінилось, рекомендуємо повне калібрування"
```

Зміни baseline/offset зберігаються тільки для поточної сесії і не
перезаписують профіль.

## 8. Метрики сесії

Рахуються з таблиці переходів станів `focus_events`. Враховується тільки
час **робочих фаз** Pomodoro.

```
T_focused     = час у FOCUSED
T_not_focused = час у NOT_FOCUSED
T_lost        = час у LOST_FOCUS + RECOVERING
T_tracked     = T_focused + T_not_focused + T_lost

focus_ratio        = (T_focused + T_not_focused) / T_tracked
n_lost_episodes    = кількість переходів NOT_FOCUSED → LOST_FOCUS
mean_lost_duration = T_lost / n_lost_episodes           (0, якщо епізодів немає)
longest_focus      = найдовший неперервний відрізок без LOST_FOCUS/RECOVERING
lost_by_reason     = розподіл n_lost_episodes за reason у момент переходу
```

Короткі погляди вбік (`NOT_FOCUSED` < n) **не** вважаються втратою фокусу.

Графік концентрації: час розбивається на біни (`10 с` наживо, `60 с` в
історії):

```
focus_share(bin) = час у {FOCUSED, NOT_FOCUSED} у біні / тривалість біну     ∈ [0,1]
```
